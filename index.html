Project Summary

Problem, solution, and value proposition

Everything judges need in one scroll.

The Problem

E-commerce loses revenue silently.

Cart abandonment, failed payments, and high-intent browsing often go unaddressed because teams lack real-time, contextual recovery workflows. Existing tools are reactive dashboards, not proactive agents.

The Solution

An autonomous agent council.

Nexora detects events, analyses intent, assesses risk, recommends recovery actions, explains the reasoning, asks for human approval, and executes through PayPal and Bloomreach/Loomi MCP.

Target Users

Operations and marketing teams.

E-commerce operators, growth managers, and customer retention teams who need to recover revenue without building complex automation from scratch.

Value Proposition

Faster recovery, human control.

Nexora reduces time-to-action from hours to seconds while keeping humans in the loop for every revenue-impacting decision.

MCP Usage

How Nexora uses Loomi Connect MCP

MCP keeps the agent workflow modular: agents request analytics, marketing, or conversation context through tool calls.

📊

Analytics tools

The Commerce Agent requests customer purchase history, AOV, segment, and recovery context through MCP analytics tools.

📨

Marketing tools

The Action Agent triggers recovery emails through Bloomreach/Loomi MCP with dynamic variables such as name and coupon.

💬

Conversation tools

The Intent Agent uses session or search signals to understand whether a visitor is browsing or highly likely to convert.

Specific use in agents

MCP turns disconnected tools into agent actions.

1

Commerce Agent

Uses analytics context: previous purchases, AOV, and customer value tier.

2

Intent Agent

Uses event/session context: checkout reached, search behaviour, abandonment type.

3

Action Agent

After human approval, calls marketing/email tools and passes dynamic recovery variables.

4

Audit Agent

Records whether the action used live APIs or demo fallback mode.

# Example MCP-style workflow Commerce Agent: call get_customer_analytics input: customer_id, project_id output: purchases, AOV, segment Intent Agent: call conversation/session search input: session_id or customer event output: intent signals Action Agent: call send_transactional_email input: customer_name, offer, payment_link output: sent / failed / fallback Audit Agent: log mode, payload, result, approval
Honest demo note: In the hackathon prototype, live MCP and PayPal Sandbox calls are attempted where configured. If a live call fails because of sandbox limits, endpoint access, or network issues, Nexora uses deterministic fallback mode and clearly labels the result as Demo Mode instead of pretending it was live.
Responsible AI

Guardrails, privacy, and human oversight

Nexora is designed to support autonomous commerce actions without removing human control.

👤

Human-in-the-loop

No revenue-impacting action is executed without explicit operator approval.

🛡️

Risk blocking

If the Risk Agent detects high fraud/payment risk, the workflow is blocked or sent to manual review.

💡

Explainability

The operator receives a clear rationale before approving any customer action.

🧾

Audit trail

Every session records agent outputs, approval status, execution mode, and results.

Privacy

Minimal customer data by design.

The prototype only needs session-level customer context such as customer ID, event type, cart value, risk score, and campaign variables. In production, customer identifiers should be hashed or tokenised, and audit logs should follow a clear retention policy.

Operational safety

Autonomy does not mean reckless execution.

Nexora proposes actions autonomously, but the approval gate controls external execution. The UI also shows Live API Mode or Demo Mode so operators understand whether real external systems responded.

Responsible AI note for submission: Nexora uses human-in-the-loop approval before executing any revenue-impacting action. The Risk Agent checks for fraud, failed payment, chargeback, and suspicious behaviour signals before execution. Every recommendation includes a human-readable explanation, and every action is logged with session ID, timestamp, approval status, execution mode, and result. Customer information is used only for the current workflow and should be minimised, tokenised, and governed by retention rules in production.
Accessibility & Inclusion

Agentic AI must work for everyone.

People with disabilities are often left out of AI product design. We built Nexora with real accessibility research, disability-community feedback, and inclusive design patterns. This is not a checkbox — it is a core value.

♿

Real Support, Not Automation

For users with motor, vision, or cognitive disabilities, agentic AI should assist, not replace. Nexora's explainability layer helps screen-reader users understand why an action is recommended before any button is pressed.

👁️

Vision-Accessible by Default

High-contrast focus indicators, semantic HTML, ARIA labels, and reduced-motion support are built in. The dashboard is navigable by keyboard alone and tested with screen readers.

🧠

Cognitive Clarity

We use plain language, predictable patterns, and progressive disclosure. No jargon walls. Every agent output is summarised in a human sentence first, technical detail second.

🗣️

Neurodiversity & Communication

Async approval workflows respect different processing speeds. Clear status badges, colour + icon redundancy, and consistent layout reduce cognitive load for neurodivergent operators.

🤝

Community-Driven Findings

We interviewed operators with disabilities and learned that trust is the biggest barrier. Transparent agent reasoning, audit trails, and easy rollback build that trust.

🌍

Global & Local

Localization-ready structure, scalable font sizes, and RTL support in the CSS foundation mean Nexora can serve diverse teams and customers worldwide.

Our Findings

What we learned from the disability community

  • Explainability is accessibility: When an AI explains itself in plain language, it helps everyone — especially users who cannot rely on visual cues alone.
  • Approval gates reduce anxiety: Autonomous systems can feel threatening to users with cognitive disabilities. A clear "you are in control" message changes the entire experience.
  • Fallback modes matter: When live APIs fail, clear "Demo Mode" labels prevent confusion. Ambiguous status updates are a major pain point for screen-reader users.
  • Keyboard navigation is non-negotiable: Many assistive technologies depend on keyboard focus. Every interactive element in Nexora is reachable without a mouse.
  • Respect pacing: Not every operator can review a recommendation in 5 seconds. The UI never auto-advances or times out.

Operator Manual

How to use Nexora — step by step

A living manual you can reference while operating the agent council.

🚀 Getting Started

Welcome to Nexora. This manual will guide you from your first login to your first approved recovery action.

  • Login: Open the dashboard and verify your operator profile.
  • Connect: Link your Bloomreach project and PayPal Sandbox credentials in Settings.
  • Watch: The event stream will begin showing customer events automatically.
  • Learn: Complete the Learning Lab quiz to unlock advanced operator permissions.

Tip: Use the Tab key to navigate any panel without a mouse. Every button has a visible focus ring.

📊 Dashboard Guide

The dashboard has four main zones. Learn them once, operate confidently forever.

  • Event Panel (left): Incoming customer events — cart abandonment, failed payments, VIP alerts.
  • Agent Council (center): Live reasoning from each agent. Green = good, amber = caution, red = blocked.
  • Explainability (right): A human-readable summary of why the recommendation was made.
  • Action Bar (bottom): Approve, reject, or snooze. You are always in control.

Accessibility: All status colours are paired with icons and text labels. Screen readers announce agent states automatically.

✅ Approval Flow

Every revenue-impacting action stops at the Human Approval Gate. Here is exactly what happens:

  • Step 1 — Detect: Nexora detects an event and routes it to the Orchestrator.
  • Step 2 — Analyse: The Agent Council runs in parallel: Intent, Commerce, Risk, Marketing.
  • Step 3 — Explain: You see a plain-language summary, expected recovery value, and risk level.
  • Step 4 — Decide: Click Approve to execute, Reject to cancel, or Snooze to review later.
  • Step 5 — Audit: The action is logged with session ID, timestamp, and execution mode (Live or Demo).

Remember: If you reject an action, Nexora learns from your feedback and adjusts future recommendations.

🤖 Agent Deep Dive

Meet the seven agents that power Nexora:

  • Intent Agent: Reads session signals — pages viewed, time on site, search queries — to score conversion likelihood.
  • Commerce Agent: Pulls purchase history, AOV, and customer lifetime value to personalise the recovery offer.
  • Risk Agent: Flags fraud, chargebacks, failed payments, and suspicious behaviour before any action is proposed.
  • Marketing Agent: Chooses the best channel (email, SMS, push) and incentive (discount, free shipping, none).
  • Explainability Agent: Translates agent outputs into one human sentence. No black boxes.
  • Action Agent: Executes the approved action through PayPal or Bloomreach/Loomi MCP.
  • Audit Agent: Records everything — inputs, outputs, approval, mode, result — for compliance and trust.

🔧 Troubleshooting

Common issues and how to fix them without stress:

  • "Demo Mode" badge: Live API credentials may be missing or sandbox limits hit. Check Settings → Integrations.
  • No events appearing: Verify your event webhook URL and that the ingestion API is running.
  • Agent council slow: Large customer histories can slow the Commerce Agent. Enable "Fast Mode" in settings to sample recent orders only.
  • Approval button disabled: The Risk Agent may have blocked the action. Read the red warning and escalate to a senior operator if needed.
  • Screen reader not announcing: Ensure your browser is at 100% zoom. Nexora uses ARIA live regions that some browsers suppress when zoomed.

⌨️ Keyboard Shortcuts

Speed up your workflow without a mouse:

  • A — Approve current recommendation
  • R — Reject current recommendation
  • S — Snooze / review later
  • E — Expand explainability panel
  • 1 – 7 — Jump to specific agent detail
  • ? — Open this shortcuts help
  • Tab / Shift+Tab — Navigate forward / backward
  • Enter / Space — Activate focused button

All shortcuts are announced to screen readers via ARIA live regions.
